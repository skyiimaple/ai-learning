# Agent 工程 · Agent loop（第 2 讲）

> 导航：[目录](./README.md) · 上一讲：[01 · Tool calling 协议](./01-Tool-calling-协议.md) · 下一讲：[03 · 记忆与上下文](./03-记忆与上下文.md)

## 这一讲解决什么

第 1 讲是「单次（或一轮）怎么调工具」。  
第 2 讲讲：**怎样反复调**，以及**什么时候停**——这就是 **Agent loop（智能体循环）**。

一句话：Agent = Tool calling + **带停止条件的循环**。

## 循环长什么样

伪代码心智模型（前端可当成 `while` + 异步副作用）：

```text
messages = [用户问题, …]
while True:
    回复 = 调用模型(messages, 工具定义)
    if 回复里没有 tool_calls:
        把最终文本交给用户
        break
    for 每个 tool_call:
        结果 = 执行工具(name, arguments)
        messages.append(tool 回执)
    # 带着新观察，再进下一轮
    if 触达停止条件:  # 见下文
        break / 降级回答
```

和「只调一次工具就结束」的差别：模型看到 observation 后，还可以再决定下一步。

## 每一轮在干什么

| 步骤 | 谁做 | 产出 |
|------|------|------|
| 推理 / 选动作 | 模型 | 最终文本，或一批 `tool_calls` |
| 执行 | 运行时 | 真实副作用 + `tool` 消息 |
| 观察回填 | 运行时 | 更新 `messages` |
| 再决策 | 模型 | 继续或收工 |

记住第 0 讲的三件套：目标 → 工具 → 观察；loop 就是把「观察 → 再决策」转起来。

## 停止条件（必须设计，不能靠感觉）

常见硬停止（建议至少设 2～3 个）：

1. **模型不再发起 tool_calls**（正常收工）  
2. **最大步数**（如 5～10 步），防止死循环  
3. **超时 / 预算**（墙钟时间、token、费用）  
4. **同一工具同一参数反复失败**（熔断）  
5. **用户取消 / 人工接管**（产品侧）

软策略（可选）：

- 工具失败：有限次重试 → 降级文案（标明不确定）→ 停止  
- 缺信息：向用户追问一句，而不是瞎调工具

没有停止条件的 loop，不是 Agent，是定时炸弹。

## 消息怎样堆积

每一轮都会把新的 `assistant`（含 tool_calls）和 `tool` 回执追加进上下文。  
上下文会变长，带来：

- 费用与延迟上升  
- 模型注意力被旧轨迹干扰  

工程上常做的事（先有概念，细节后讲）：

- **裁剪**：丢掉早期无关轮次，保留目标与最近观察  
- **摘要**：把长轨迹压成短状态  
- **分会话**：子任务用新消息列表，只把结论带回主对话

## 和 Tool calling、工作流的边界

| | Tool calling（单轮倾向） | Agent loop | 固定工作流 / 编排 |
|--|-------------------------|------------|-------------------|
| 下一步谁定 | 常是你写死或一次调用 | **模型**动态定 | **你**预先画好图 |
| 步数 | 少 | 不固定 | 固定或分支固定 |
| 适合 | 查一下就答 | 目标开放、路径多变 | 合规、强可控流程 |

实践里三者常混用：外层工作流，内层某节点跑一小段 Agent loop。

## 失败怎么处理（最小集）

| 情况 | 建议 |
|------|------|
| 参数非法 | 校验失败：把错误当 observation 回给模型，或直接停并提示 |
| 工具超时 | 短重试 1 次 → 降级 / 停止 |
| 工具抛错 | 结构化错误信息回填；勿把堆栈整页塞进上下文 |
| 模型乱调 | 收紧 schema / 描述；加大「何时不该调用」说明 |
