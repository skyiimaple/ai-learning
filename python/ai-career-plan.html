🛤️ 三条转型路径

🅰️ AI 应用开发 推荐主线

用 LLM API 做产品：Prompt、RAG、Agent、Streaming UI。门槛最低、前端优势最大、6 个月出成果。岗位：AI 全栈 / AI 产品工程师

🅱️ ML 工程师 选修加深

训练/微调/部署模型。需要扎实数学和 ML 基础，周期 12-18 个月。岗位：MLE / 算法工程师

🅲️ MLOps / AI Infra

AI 基础设施和工具链。工程能力要求最高，前端工程化经验全能用。岗位：MLOps / AI Platform

本版策略：主线只走 A。月 1–4 交付可用产品；数学 / sklearn / PyTorch 收成「选修包」，卡壳再补。站稳后按兴趣向 B 或 C 深入。

📅 A路线 · 6个月详细计划

🔹 第 1 个月：Python 速通 + FastAPI + LLM API

目标：能写 Python 服务、调通模型 API、前端打通 Streaming

第1-2周：Python 语法速通（有 JS 基础，两周够）

  • 和 JS 对比学：缩进、类型、列表推导式、字典/集合/元组、*args/**kwargs、装饰器
  • 文件与数据：json / csv、with open()、异常处理、venv + pip
  • 异步：asyncio / httpx（对标 Promise/fetch）——后面接 Streaming 会用到
  • 实战 CLI 脚本：读 JSON/CSV → 统计 → 输出结果 [Python教程]
  • 不做 本月不深挖 OOP 百科全书、不啃完整教材

第3周：FastAPI + SQL 够用版

  • FastAPI：路由、Pydantic、依赖注入、CORS——对标 Express + Zod
  • SQL 只学够用：SELECT / WHERE / JOIN / GROUP BY / LIMIT（3–5 天）
  • Python 取数：pandas.read_sql 或 SQLAlchemy 基础 CRUD
  • GUI：DBeaver；练习可用 SQLite，生产感再上 PostgreSQL
  • 实战 FastAPI 提供 CRUD + 一个聚合查询接口
  • 延后 索引优化、百万级表、完整电商 RFM——有余力再做

第4周：调通 LLM API + Streaming

  • 先接一个国内模型（DeepSeek / 通义 / 豆包）+ 一个对照（OpenAI/Claude）
  • Chat Completions、System Prompt、多轮历史、Token 与成本意识（tiktoken 或厂商计费）
  • Streaming：SSE；前端用 fetch + ReadableStream 或直接上 Vercel AI SDK
  • 实战 FastAPI Streaming 接口 + Next.js 简单 Chat 页跑通端到端
  • 参考：Vercel AI SDK | OpenAI Chat | DeepSeek API

🔹 第 2 个月：Prompt + Tool Calling + 前端 AI 产品

目标：做出带工具调用的 Chat 产品，把前端优势打出来

第5-6周：Prompt Engineering + 结构化输出

  • Zero-shot → Few-shot → Chain-of-Thought → ReAct 思路
  • System Prompt 设计、角色边界、输出格式约束
  • 结构化输出：JSON mode / schema（后面 Agent、评测都靠它）
  • 安全基础：Prompt 注入意识、密钥不进前端、基础限流
  • 实战 AI 翻译/写作助手：术语表、风格、Streaming、可切换模型

第7-8周：Function Calling / Tools + Next.js 产品化

  • Tool Use：让模型调你写的函数（查天气、查库、算数、调内部 API）
  • 前端：Next.js + Vercel AI SDK 的 useChat / tool UI 渲染
  • 对照读源码：chatbot-ui（看前端怎么接 AI，不要整站抄）
  • 实战 带 2–3 个 Tool 的 Chat 应用（例如：查 SQLite + 画简单图表 + 网页摘要）
  • 短课：DeepLearning.AI short courses（LangChain/Functions 任选 1–2 门，各约 1h）

🔹 第 3 个月：RAG 全链路（核心产出期）

目标：独立交付个人知识库问答，并有最简评测

第9-10周：RAG 架构与实现

  • 链路：提问 → Embedding → 向量检索 → 拼 Prompt → LLM 回答 → 引用展示
  • 文档处理：PDF/MD/HTML → 文本 → Chunking（固定/递归，先别纠结语义切）
  • 向量库：Chroma 快速跑通，或 PostgreSQL + pgvector（一个库兼顾结构化+向量）
  • 框架：LlamaIndex 或 LangChain 选一个深用，另一个知道即可
  • 实战 把你的笔记/项目文档做成问答助手，前端 Chat UI 展示引用来源
  • 参考：privateGPT | pgvector | Chroma

第11-12周：检索优化 + 评测（拉开差距）

  • 检索优化：Hybrid Search、简单 Re-Ranking、Query Rewriting（先各试一种）
  • 必做 手工建 20 条黄金问答集：问句、应命中文档、期望答案要点
  • 评测指标（够用版）：检索命中率、回答是否 grounded、明显幻觉计数
  • 观测：接入 Langfuse（或同类）看 prompt、延迟、token 成本
  • 产出 必交项目 ⭐「个人知识库」：README + 架构图 + 本地可跑 + 评测记录

🔹 第 4 个月：Agent + 毕业项目 MVP

目标：交付 1 个可演示的 Agent 项目（二选一做深）

第13-14周：Agent 核心能力

  • 循环：Thought → Action → Observation；何时停、如何限步数
  • Memory：短对话缓冲 / 摘要 / 向量记忆（按项目需要选）
  • 多工具编排、失败重试、人机确认（高风险操作要确认）
  • 本地模型：Ollama 跑 Qwen / Llama，理解云端 vs 本地权衡
  • 实战 最小 Agent：能串 3 个以上工具完成一个真实任务

第15-16周：毕业项目 MVP（二选一）

  • 方向① AI 代码审查助手：接 GitHub Webhook/API，PR 自动 Review（安全/规范/潜在 Bug） [PR-Agent]
  • 方向② AI 数据分析助手：上传 CSV → 自然语言 → SQL/Python → 图表+结论 [pandas-ai]
  • MVP 标准：主流程通、有 Chat UI、有错误处理、能给别人演示 3 分钟
  • 不做 同时开两个毕业项目；Dify 可以参考编排思路，但简历项目要自己写核心链路

🔹 第 5 个月：工程化打磨 + 上线

目标：从 Demo 变成可写进简历的完整项目

第17-20周：可观测、成本、安全、部署

  • 完善评测集；关键路径加日志与 tracing
  • 成本与延迟：缓存常见问、控制 context、模型分级（简单题用小模型）
  • 安全：密钥管理、注入防护、工具权限、上传文件沙箱（数据分析方向必做）
  • Docker 一键启动；部署到可访问地址；录 Demo 视频（2–5 分钟）
  • README：问题背景、架构图、技术选型、如何运行、评测结果、踩坑
  • 可选加深：看 Dify 的编排/工作流设计，反哺自己的产品化能力

🔹 第 6 个月：面试 + 按需补课

目标：能讲清项目与系统设计，按缺口补 ML/数学

第21-24周：求职准备

  • 简历定位：「前端工程化 + AI 应用开发」的全栈 AI，突出 2 个必交项目
  • 面试高频：怎么设计 RAG、如何降幻觉、Tool Calling 失败怎么办、成本怎么控
  • 补 Transformer 直觉：Illustrated Transformer + 李宏毅 GenAI 选看
  • 若目标岗偏 MLE（路线 B）：再打开下方「选修包」
  • 持续输出：每周一篇学习/项目笔记（博客或社交平台）

⚠️ 常见误区

坑1：先打一年数学/ML 再碰 LLM。A 路线应先做出 RAG/Agent；数学和 PyTorch 按需补。
坑2：觉得要会训练大模型才算入行。多数 AI 应用岗要的是 API、RAG、Agent、工程化与产品感。
坑3：放弃前端只写 Python。Next.js + Streaming UI 是差异化；「全栈 AI」比「纯算法新手」更好讲故事。
坑4：项目贪多。10 个半成品不如 2 个能演示、有评测、能部署的项目。
坑5：只看视频不动手 / 不做评测。没有黄金集和观测，RAG 很难证明「真的有用」。
坑6：闭门造车不分享。持续输出学习笔记，逼自己讲清楚，也利于求职曝光。
